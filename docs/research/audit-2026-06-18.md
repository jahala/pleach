# Whole-project audit — 2026-06-18

**Scope:** the entire pleach repo at master `a19e0c6` (post-generalization, post-umbel-rename).
**Method:** 5 parallel specialist review agents (architecture/S.U.P.E.R., code quality, testing,
security/concurrency, contract/rename/docs), each auditing against the binding doctrine
(`ENGINEERING.md` + `.claude/CLAUDE.md`); then a tech-lead verification pass that re-read the
high-impact code findings and re-calibrated every severity. Severities below are **mine** (post-verification),
not the raw agent labels.
**Baseline:** `bun run check` green — 191 pass / 13 skip / 0 fail; `biome check` clean (48 files); `tsc` clean;
layer-import discipline clean (zero cross-layer reaches found).

## Verdict

The codebase is **genuinely healthy**. Layering, ports-and-adapters, the concurrency invariants
(commit-before-emit, closed-then-dispose, single-ingester, O_EXCL lock), the SEC1 arg-array trust boundary,
and the test architecture (real in-memory seam doubles, not behavior-mocks; byte-for-byte drift test) are all
sound and structurally enforced. The audit's value is a **short list of real-but-small code fixes** plus
**documentation drift** introduced by the recent refactor+rename — not structural problems.

## Corrections (agent over-claims I downgraded)

Transparency on what the verification pass caught:

- **Security "HIGH": seeded-dep baseRef falls back to an unverified branch name** (`run-plan.ts:315`) —
  **false positive.** The startup-reconciliation loop (`run-plan.ts:76-88`) resolves `baseRefForClosed` for
  *every* closed dep of *every* pending node, and `settle` populates it on run-close (`:233`). The `?? node/<d>`
  fallback is defensive and unreachable for a legitimately-scheduled node. (A *real, lower-severity* point hides
  underneath it — see SHA-pinning, LOW below.)
- **Security/Code "HIGH": exec drains corrupt `output` via concurrent mutation** (`exec.ts:36-49`) —
  **false positive.** The interleave is intentional and documented (`exec.ts:3-5`); JS is single-threaded so
  `output +=` never tears. (A *real LOW* hides underneath — the missing final decoder flush.)
- **Architecture "MEDIUM": `umbelRunner`/`gitLedger` hardwire the `exec` seam** — **not a violation.**
  `ENGINEERING.md:70` explicitly sanctions "an `adapters/` bridge may also use a `seam/` (e.g. the audited
  `exec`)", and the injectable `createUmbelSeam(exec, …)` core exists for tests. Production wiring using the
  default `exec` is by design.
- **Code "CRITICAL": `argv.ts` bare `new Error`** — real, but **MEDIUM**, not critical (no crash/security/data-loss).

## Findings (worth acting on)

### Code

- **[MEDIUM] `core/argv.ts:57` — bare `new Error` (the one clear doctrine breach).** ENGINEERING.md §4: "No
  bare `new Error` outside `core/errors.ts`." `toArgv` throws a plain Error on an unterminated quote, so the
  face can't pattern-match it and it falls to the generic `exit 1` instead of a usage `exit 2`. **Fix:** add
  `ArgvParseError` to `core/errors.ts`, throw it, map it to exit 2 in `cli.ts`. *(Test-first: a plan with a
  malformed quoted command should exit 2.)*
- **[MEDIUM] `faces/config.ts:54-65` — config shape validation is too shallow.** `loadConfig` checks
  `runner`/`ledger` are non-null objects but not that they carry `spawnWorker` / `readClosed`+`emitVerdict`.
  A `pleach.config.ts` exporting `{runner:{}, ledger:{}}` passes, then dies deep in `runNode` with an
  uninformative `TypeError` instead of a clean `ConfigError` (exit 2) at the boundary. **Fix:** duck-type the
  methods in `loadConfig`, throw `ConfigError`.
- **[LOW] `seams/exec.ts:45` — `TextDecoder` never flushed.** `decoder.decode(value, {stream:true})` buffers
  an incomplete trailing multi-byte sequence that is then dropped (no final `decoder.decode()` after the loop).
  Bites only on truncated/non-ASCII output ending at a chunk boundary — rare for git/test output, but a real
  latent correctness nit. **Fix:** append `output += decoder.decode();` after each drain's loop.
- **[LOW-MEDIUM] `run-plan.ts:218` + `run-node.ts:gateExitCode` — structured gate `exitCode` is a `-1`
  placeholder** for `command`/`red`/`green`/`marker` gate failures (the real code is only in the evidence
  *prose*). `GateFailedError` carries no `exitCode` field. **Fix (optional):** add `readonly exitCode` to
  `GateFailedError` and thread it; the `marker` gate legitimately has no code.
- **[LOW-MEDIUM] `run-plan.ts:233` + `resolveBaseRef:304` — isolate bases are branch *names*, not pinned SHAs.**
  Even though the verified `sha` is in hand at `:232`, dependents isolate from the movable `node/<id>` branch
  (and `resolveBaseRef` prefers the branch over the recorded SHA on resume). Given trusted plans + trusted
  workers this is defense-in-depth, but pinning the verified SHA would close the "never trust a ref a worker
  could have moved" gap the doctrine names. **Fix (hardening):** store/return the SHA; or verify the branch
  resolves to the recorded SHA.
- **[LOW] `seams/isolate.ts:137` — `git add -A` in the conflict-commit path** violates the scoped-staging
  principle (ledger S1/C2). Safe *here* (pre-worker worktree, only merge-generated conflict files exist) but
  undocumented. **Fix:** a one-line comment, or `git add -u`.
- **[LOW] `seams/isolate.ts:dispose` — `tmpBase` (the `mkdtemp` dir) is leaked.** `git worktree remove` drops
  the `wt/` subdir but not its parent; empty `pleach-*` dirs accumulate across runs. **Fix:** `fs.rm(tmpBase)`
  after worktree removal (pleach owns it). Also: `dispose` silently swallows unrecognized non-zero `git
  worktree remove` exits — journal them.

## Strengths (verified, not assumed)

- Strict downward deps with **zero** violations; `core/` is pure with no I/O; the loop receives all seams by
  injection and imports no seam/adapter module.
- Error taxonomy: discriminated subclasses in `core/errors.ts`, typed catches at the face, no unknown-error
  silent retry.
- Concurrency invariants are *structurally* enforced (commit-before-emit, closed-then-dispose ordering,
  serial ledger queue, O_EXCL lock) and have ordering-assertion tests, not just outcome checks.
- SEC1 end-to-end: `toArgv` is a pure/total POSIX splitter, no `sh -c` anywhere, `Bun.spawn` gets the argv
  directly; `Node.id` regex is tight.
- The drift test is genuinely discriminating (byte-level `toBe`); the in-memory harness is a real seam
  implementation, not a mock.
- No `any`, no `console.log`, no `TODO`, no committed stubs/mocks in `src/`.
