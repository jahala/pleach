# `@agent-contract/plan` v1.2 — the ratification draft

**Status: PROPOSAL (2026-08-19)** — converged on-channel (per-amendment AGREE from both
sides, prose requirements folded); this document is the text submitted for tend2's formal
ratification. Deliberately NOT yet in the canonical schema block: the canonical block never
describes fields the conductor does not honor — on ratification, each amendment's
IMPLEMENTATION moves its field into `plan-schema.md`'s fenced block (doc + source + drift
test + CHANGES, one commit per the contract law) and the feature goes live whole. Four
amendments, all backward-compatible (optional fields; absent = exactly today's behavior).

## 1. Retry escalation — `policy.escalation?: string[]`

```ts
// In Node.policy (v1.2):
escalation: z.array(z.string()).optional(),   // model names; attempt N (N≥2) runs escalation[N-2]
```

**Binding semantics (contract prose, not implementation whim):** attempt N runs with model
`escalation[N-2]`, saturating at the last entry. **The provider NEVER changes** — audit
diversity must survive escalation; a provider ladder is deliberately impossible. WHICH
failure classes climb is runner policy (pleach v1: only gate failures climb; timeout and
process-death hold the model — wall clocks and dying processes are not capability signals).

## 2. Typed refusal — `Verdict.status += 'refused'` + `evidence.refusal`

```ts
// Verdict.status gains 'refused'; Verdict.evidence gains:
refusal: z.object({
  kind: z.enum(['scope_exceeded', 'underspecified', 'blocked_on_dependency']),
  detail: z.string(),   // scope_exceeded: the proposed split, one line per subtask;
                        // underspecified: the question; blocked_on_dependency: the dep
}).optional(),
```

**Binding semantics:** a worker signals refusal via a ```pleach-refusal``` fenced JSON
block in its final message — the same egress discipline as the audit fence: LAST block
wins, parsed never interpreted, an unknown kind is a contract violation and routes as an
ordinary failure. A parsed refusal is TERMINAL: no retry burn, no branch, its own summary
bucket (`refused[]`), narrated as needs-a-human. The conductor NEVER acts on a proposed
split — splits are planner jurisdiction (the ledger receives the verdict like any other
non-done; what the planner does with the split is its own design space).

## 3. Run budget — `Plan.budget?: { maxTokens }`

```ts
// In Plan (v1.2):
budget: z.object({ maxTokens: z.number().int().positive() }).optional(),
```

**Binding semantics:** spend = the sum of verdict telemetry tokens for this `plan.source`
across the JOURNAL (cumulative across resumes by construction). At 80%: a warning (journal
+ narration). At cap: stop scheduling; in-flight nodes run to their verdicts (never orphan
a worktree mid-gate); unscheduled nodes report `skipped` with the budget reason; the
summary says so. **Normative, both implementations bound:** a runner that cannot count
tokens for a node MUST surface an "unenforceable for N node(s)" warning — never silently
pretend enforcement. No USD anywhere in the contract: tokens are measured and
provider-neutral; pricing is a consumer concern (the casting ledger's, not the plan's).

## 4. Context manifests + work-order by reference

```ts
// In Node (v1.2):
context: z.array(z.object({ file: z.string(), reason: z.string() })).optional(),
// In the Work union (v1.2) — a fourth member, mutually exclusive with {prompt}:
z.object({ promptPath: z.string() }),
```

**Binding semantics:** both `context[].file` and `promptPath` resolve IN THE NODE'S
WORKTREE, post-merge — a dependency's conventions doc written by a verified parent is
readable by construction. A missing file is a GATE FAILURE (fail closed), identical
semantics for both. Composition when both are present: the context block is the stable
prefix (file contents, each introduced by its declared reason), then the promptPath
content, then any retry evidence — stable-prefix ordering is deliberate (prompt-cache
locality is free money). The emitted work order is thereby fully reviewable in the repo:
plans reference prose, they don't embed it.
