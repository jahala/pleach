why pleach

you can't trust an agent's "done"

An agent grades its own work green. Reviewing every diff defeats the point of delegating. The only honest answer is mechanically enforced gates, run by code the agent did not write.

✗ without pleach

A node agent declares its work done. Its branch is merged by downstream nodes. A broken implementation propagates down the DAG: wrong logic, unchecked conflict markers, a red smoke suite the agent quietly ignored. By the time anyone notices, 3 dependent nodes have built on top of garbage.

✓ with pleach

Gates run before any branch is published. A node that fails conflict-marker scan, smoke, or cross-provider audit is quarantined: no branch, no dependents built on it. Only verified work reaches the next layer of the DAG. Garbage stays isolated at the point of production.

the loop, walked

5 deterministic beats per node

Every node in the plan passes through the same fixed ladder. The agent touches only beat 2, and everything else is code.

1
isolate

A detached git worktree is created from the verified branches of every upstream dependency. The agent starts from a clean, merged baseline, never from trunk directly.

git worktree add --detach node/<id>
2
work

The configured runner drives the worker inside the worktree: one unit of agent work, isolated, observable. This is the only beat the agent controls. Two runners ship in the box: umbel drives interactive agent CLIs in tmux; direct-cli needs only the claude and codex CLIs on PATH. A pleach.config.ts swaps in any other.

pleach run plan.json --runner direct-cli
3
gates

Conflict-marker scan catches unresolved merges. Smoke runs the node's declared test command. Cross-provider audit re-runs the plan's check command in a fresh session from a different vendor. If claude built the node, codex audits, so no model grades its own work.

4
commit before emit

The node/<id> branch is written to git before the ledger is notified. The source of truth is the git object store, not an API response that could fail mid-flight.

5
publish

Only verified nodes publish a node/<id> branch. Dependents build from that branch, and pleach land merges the verified result onto your working branch. A failed node publishes no node branch. Its final tree is kept on quarantine/<id> as evidence, and its dependents are skipped, not built on a bad base.

gates

no model grades its own work

3 gates run in order. Each must pass before the next begins.

Conflict-marker scan. A literal string search for <<<<<<< in every tracked file. No parse, no heuristic. A marker present means the node is quarantined immediately.

Smoke. The node's declared test command runs inside the worktree. The test suite the agent itself wrote must pass. A red suite means the node never had a credible claim to done in the first place.

Cross-provider audit. An agent from a different vendor re-runs the plan's check command in a fresh session and relays its machine-parsed verdict. If claude built the node, codex audits. The auditor executes; it does not opine: and pleach refuses to run a gate the builder edited, so a node cannot rewrite its own audit. This is the gate that makes the others honest.

Quarantine. A failed node publishes no node branch. Its final tree is kept on quarantine/<id> so the evidence survives. Its dependents are skipped, they are not built on a bad base, and they are not marked failed either. They wait until the upstream is resolved.

honest scope

when to reach for pleach, and when not to

for
  • Unattended multi-step agent builds where gates decide what lands
  • A concrete plan: a real DAG of nodes, not a vague list (tend2, the bundled pleach-plan skill, or any planner)
  • Work you will not review diff-by-diff yourself
  • Projects where a bad node silently poisoning its dependents is not acceptable
  • Teams that need audit evidence, not just a green suite
not for
  • A single quick edit you'll review before merging
  • Interactive pairing sessions where you're guiding each step
  • Anything you'll hand-review anyway; the gates add overhead for no benefit
  • Projects without a concrete plan first, though the bundled pleach-plan skill will write one with you

start

run a plan, land only what's verified

pleach validate plan.json
pleach run plan.json --runner direct-cli
pleach land plan.json

Part of the plotplot garden. pleach runs standalone on git + any agent tool. With the claude and codex CLIs on PATH, --runner direct-cli needs nothing else; the bundled examples run on git + bun alone, no agent and no API keys; and your own code can drive the conductor with import { runPlan } from 'pleach'. tend2 and umbel are the batteries-included reference adapters; swap either via pleach.config.ts.
